# 01. 用語集・主要概念

> **English summary**: Canonical vocabulary for this project. Defined once here and
> reused across all design docs. Terms are grouped by the three planes (work /
> execution / authorization) plus shared concepts.

ドキュメント全体で用語を統一するための定義集です。新しい概念を導入する各ドキュメントは、
ここの定義を参照します。和英を併記し、将来コード上の識別子と対応づけやすくします。

## 作業平面（Work Plane）

| 用語 | English | 定義 |
|------|---------|------|
| タスク | Task | 業務上の一つの意図を表す永続エンティティ。URL を持ち、可視で参照可能な「石」。状態を持ち、ワークフローに駆動される。 |
| サブタスク | Subtask | 親タスクに従属するタスク。親子は分解関係を表す。 |
| タスクリンク | Task Link | タスク間の型つきの関係（blocks / relates-to / triggered-by / approval-for 等）。 |
| 承認レコード | Approval Record | 承認ゲートで生まれる構造化された意思決定（承認／却下／要修正、条件、承認者、時刻）。 |
| 申請 | Request / Application | 承認を求めて投稿される構造化データ（例：事前申請、精算申請）。 |
| 台帳 / イベント履歴 | Ledger / Event History | タスク・ワークフローに起きた出来事の追記専用ログ。監査と再現の正本。 |
| コンテキスト / ペイロード | Context / Payload | タスクに蓄積される構造化データ（金額・経路・領収書の有無 など）。 |

## 実行平面（Execution Plane）

| 用語 | English | 定義 |
|------|---------|------|
| ワークフロー定義 | Workflow Definition / Template | 再利用可能な処理の流れの設計図。タスク種別に紐づく。ステップと遷移、各ステップの必要ロールと利用可能ツールを規定。 |
| ワークフロー実行 | Workflow Instance / Run | タスクに束ねられた、実行中のワークフローの 1 インスタンス。永続状態・現在ステップ・待機条件を持つ。 |
| ステップ / アクティビティ | Step / Activity | 処理の最小単位。種別：エージェント実行 / 人間ゲート / システム処理 / サブワークフロー。 |
| 承認ゲート | Approval Gate | 人間の意思決定を待つ特別なステップ。連鎖を中断し、承認で再開する。 |
| 状態機械 | State Machine | タスク／ワークフローが取りうる状態と、その間の許可された遷移の集合。 |
| 中断と再開 | Pause / Resume (Durable Execution) | プロセスが資源を消費せず眠り、シグナル（承認・期限・イベント）で再開する性質。 |
| シグナル | Signal | 外部から実行中インスタンスへ注入される入力（承認の押下、外部完了通知 等）。 |
| 区間処理 | Interval Processing | 「前回実行〜今回実行」の期間を対象に集約・処理する定期タスクの意味論。 |

## 認可平面（Authorization Plane）

| 用語 | English | 定義 |
|------|---------|------|
| アクター | Actor / Principal | 行為の主体。人間（依頼者・承認者・会計担当者 等のロールを持つ）またはエージェント。 |
| エージェント | Agent | タスクのステップを実行する非人間アクター。自身のアイデンティティとスコープを持つ。 |
| アイデンティティ | Identity | アクターを一意に識別し、認証可能にするもの（人は OIDC、エージェントは非人間アイデンティティ）。 |
| ロール | Role | 人間アクターに与えられる職能（承認者、会計担当 等）。権限の束ね方の一つ。 |
| 委譲 | Delegation | あるアクターが別のアクター（多くは人→エージェント）に権限の一部を預けること。常に縮小を伴う。 |
| 縮小 / アテニュエーション | Attenuation | 委譲のたびに権限集合を真に狭めること。各ホップで権限が増えないことを保証する。 |
| ケイパビリティ | Capability | 「ある資源に対する特定の操作を行ってよい」という、偽造不能で検証可能な権限の単位。 |
| スコープ | Scope | ツール・操作・資源・条件（金額上限 等）で区切られた権限の範囲。 |
| ツール | Tool | エージェントが叩ける外部機能（運賃照会、送金、メッセージ送信 等）。入出力スキーマと副作用クラスを持つ。 |
| ツールカタログ | Tool Catalog | 利用可能なツールの登録簿。各ツールのスキーマ・リスク区分・必要スコープを記述。 |
| 同意 / 確認 | Consent / Elicitation | 不可逆・重要な操作の前に人間へ可否を問うこと（Yes/No など）。 |

## 横断的概念

| 用語 | English | 定義 |
|------|---------|------|
| 監査証跡 | Audit Trail | 「誰が・いつ・どの権限で・どのツールを・どのタスクで」叩いたかの追跡可能な記録。 |
| 冪等性 | Idempotency | 同じ操作を複数回実行しても結果が一度きりと等価になる性質。再開・再送に必須。 |
| 副作用クラス | Side-effect Class | ツールの危険度区分（読み取りのみ / 可逆な書き込み / 不可逆・金銭的）。確認や承認の要否を左右する。 |
| 人間関与 | Human-in-the-loop (HITL) | 自動処理の途中に人間の判断・承認・入力を挟む設計。 |
| 定期タスク | Recurring Task | スケジュールに従ってタスク実体を生成する定義。区間処理の意味論を伴うことが多い。 |

## 用語の使い分けメモ

- **「タスク」と「ワークフロー実行」は別物**：タスクは *何を達成したいか*、ワークフロー実行は
  *いまどう進んでいるか*。1 タスクに対し主たる 1 実行を結びつけるのが基本だが、再試行や
  サブフローで複数の実行が関与しうる（詳細は [03](./03-workflow-engine.md)）。
- **「ロール」と「ケイパビリティ」を混同しない**：ロールは人間の束ね（粗い）、ケイパビリティは
  個別操作の許可（細かい）。両者の対応は [05](./05-authz-identity.md) で扱う。
- **「承認」と「同意/確認」を区別する**：承認（Approval）は*他者*による意思決定でゲートを成す。
  同意/確認（Elicitation）は*操作の直前*に実行者本人へ可否を問う UX。詳細は [07](./07-human-in-the-loop.md)。
